# PDFtutut

Редактор PDF, который работает целиком в браузере: файл не уходит на сервер, регистрации нет.

**Сайт:** https://pdftututu.vercel.app

Надоело, что онлайн-редакторы PDF просят регистрацию или подписку, поэтому сделал свой. В отличие от iLovePDF и Smallpdf, файл никуда не загружается: и правка, и сжатие, и распознавание текста идут на твоём устройстве.

## Что умеет

- редактировать PDF: добавить текст, поправить уже существующий, вставить картинку или подпись, нарисовать фигуры, выделить маркером
- заполнять формы
- объединять и разделять файлы
- поворачивать, удалять и переставлять страницы
- делать PDF из картинок и картинки из PDF
- сжимать
- ставить и снимать пароль
- распознавать текст на сканах (OCR)
- переводить PDF в Word и в текст
- ставить водяной знак и номера страниц, править метаданные, делать PDF чёрно-белым
- скрывать данные навсегда: закрашенный участок растрируется, и текст под ним из файла пропадает

Есть тёмная тема и английский язык.

## Как запустить у себя

Нужен Node.js 20 или новее.

```
npm install
npm run dev
```

Потом открыть http://localhost:3000

Ещё команды:

- `npm run build` собрать проект
- `npm test` прогнать тесты
- `npm run e2e` прогнать сценарии в браузере (Playwright, нужен `npm run build`; браузер ставится командой `npx playwright install chromium`)
- `npm run lint` проверить код

Всё это же запускается на GitHub при каждом пуше в main и в пулреквестах.

## Деплой

Сайт живёт на Vercel. Подключаешь репозиторий, жмёшь Deploy, больше ничего настраивать не надо. Дальше каждый пуш в main обновляет сайт сам.

Необязательные переменные окружения (Settings → Environment Variables):

- `NEXT_PUBLIC_SITE_URL` — свой домен, например `https://example.ru`. Без него адреса в sitemap и превью строятся от `*.vercel.app`.
- `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION` — коды подтверждения из Google Search Console и Яндекс.Вебмастера (способ «мета-тег»).

Статистика: в панели проекта включить Analytics и Speed Insights.

## На чём сделано

Next.js, TypeScript, Tailwind. Страницы рисует pdf.js, сами файлы меняет pdf-lib (форк @cantoo/pdf-lib, в нём есть шифрование). Редактор на Konva, OCR через tesseract.js.

Шрифты PT Sans, PT Serif и PT Mono лежат в `public/fonts`. Без них в PDF нельзя писать по-русски.

Файлы pdf.js и модели распознавания для OCR при `npm install` копируются из npm-пакетов в `public/pdfjs` и `public/tesseract`, так что сайт ничего не грузит с чужих CDN.

## Как устроена правка существующего текста

Менять текст прямо в командах страницы ненадёжно: шрифты в PDF обычно встроены подмножеством, и нужных букв в них может просто не быть. Поэтому правка устроена иначе.

1. pdf.js отдаёт текст страницы кусками: словами или обрывками строк со своими координатами. Берётся только горизонтальный текст.
2. Куски склеиваются в строки ([src/lib/pdf/textLines.ts](src/lib/pdf/textLines.ts)). У слов одной строки базовые линии могут немного расходиться, особенно в тексте после OCR, поэтому кусок попадает в строку, если его базовая линия отличается меньше чем на 30% размера шрифта, размер шрифта похож, а расстояние до строки не больше полутора кеглей. Внутри строки куски сортируются по x, пробел ставится там, где между ними заметный промежуток.
3. По имени исходного шрифта угадывается семейство (с засечками, без засечек, моноширинный) и начертание. Новый текст пишется похожим PT-шрифтом, он встраивается в файл и умеет кириллицу.
4. Старая строка закрывается белым прямоугольником, новая рисуется поверх.

Старый текст при этом остаётся в файле: его можно выделить и найти поиском. Если это важно, при скачивании включи «Растрировать страницы с правками текста». Тогда такие страницы сохраняются картинкой 200 dpi, и старого текста в файле не остаётся, но и выделять текст на этих страницах будет нельзя.

## Что пока не очень

- Старый текст при правке остаётся в файле, если не растрировать страницу (см. выше).
- XFA-формы не поддерживаются.
